### Recommendation: B · Spatial Workspace

Inkless Cat is a focused resume editor, so the paper and editable content should remain the clearest surfaces. Spatial Workspace gives navigation and the preview distinct places without turning the form or resume into glass. Its responsive structure also has a direct fallback at 1024px and a single-panel mobile flow. The current prototype opens on B and lets reviewers switch to A and C.

## Prototype interaction and scope

- The workspace fields, module order, module visibility, theme, visual direction, template accent, preview zoom, interview step and confirmation dialog are local React state only.
- The résumé is fictional sample content. The editor does not read or write the production Resume Store, Workspace storage, import/export contracts or print pipeline.
- AI interview questions and provider settings are presentation-only. No request is sent, no API key is accepted or saved, and no formal fact extraction or confirmation is implied.
- Import, export, Markdown and print controls explain their demo boundary instead of claiming to complete a business operation.
- The A4 preview uses a white paper surface in both application themes. Changing a template only changes its accent in this prototype.

## Design implementation rules

- Reserve translucency for the header, desktop navigation, mobile switcher, menus, dialog and toast. Keep form controls opaque and the A4 document white.
- Keep visual tokens local to the prototype stylesheet: surfaces, type, radius, shadows, blur, motion and z-index. Use CSS and the existing Tailwind/Vite setup; add no animation or icon dependencies.
- Use the project’s own Inkless Cat mark and custom inline line icons. No Apple marks, system icons, external photographs, web fonts or third-party visual assets are included.
- Provide a solid-surface fallback when backdrop filtering is unavailable or the user requests higher contrast, visible focus, keyboard-operated navigation, reduced motion and safe-area padding on mobile.
- Use template radio controls for style choice and explicit up/down controls for keyboard-accessible module order.

## Phase 4B–4D proposal

1. **Phase 4B — Confirm direction and establish shared visual tokens.** After review, select a direction and settle color, spacing, type, contrast and responsive tokens. Keep the prototype route isolated; add no Resume Store or persistence changes.
2. **Phase 4C — Migrate the editor shell in slices.** Replace the production top bar, navigation and editor surface behind explicit component boundaries. Then move module management, template selection and the A4 preview one at a time, reusing their existing models and renderer. Compare content and print output against current contracts after each slice.
3. **Phase 4D — Migrate AI, settings and I/O surfaces.** Restyle provider configuration, interview, fact review, confirmation and notifications while retaining existing key protection, interview state, human confirmation, session isolation, Undo/ABA handling and export semantics. Remove the experiment route only after the selected implementation has its own review evidence and all existing business regressions pass.

Each phase should remain a separate reviewable PR. Do not replace the production editor or begin Phase 4B from this Phase 4A branch.
